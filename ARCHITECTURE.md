# Архитектура DEO AutoLang

## Принцип границ

Сайт и платформа — отдельные продукты с разными API, хранилищами и администраторами. Сайт может работать, даже если платформенные сервисы остановлены. Платформа может получать проверенные записи из базы через внутренний API. Направление интеграции только одно: `FastAPI → Base Django`; сайт не подключён к платформенным сервисам.

```text
Браузер ── /site-api ──> backend_side (Django/DRF/Jazzmin) ──> db.sqlite3
                                      отдельный каталог сайта

KMP / Console (по мере подключения) ──> deo_auto_lang_backend (FastAPI)
                              │
                              └── service key ──> deo_auto_lang_base/catalog_backend
                                                       │
                                                       ├── catalog.sqlite3
                                                       └── закрытое хранилище пакетов ПО
```

## Владение данными

| Данные | Единственный владелец | Правило доступа |
| --- | --- | --- |
| Обращения формы и публичные записи сайта | `backend_side/` | Только website API и админка сайта |
| Проверенные конфигурации, файлы ПО, контрольные суммы | `deo_auto_lang_base/catalog_backend/` | Админка базы; проверенный каталог читает только FastAPI по сервисному ключу |
| Общие Kotlin-типы и правила точного совпадения | `deo_auto_lang_base/src/` | KMP-компиляция; без доступа к Django данным |
| Сессии и операции платформы | `deo_auto_lang_backend/` (дальнейшая разработка) | Платформенный API; не является backend сайта |

Список совместимости сайта курируется отдельно. Его добавление или обновление — ручной процесс после проверки; синхронизация между базами намеренно не настроена.

## Направление зависимостей

- `domain/` — чистые правила проверки конфигураций и пакетов; без Django, HTTP и хранилища.
- `application/` — прикладные сценарии, порты и DTO; не обрабатывают HTTP и не строят ORM-запросы.
- `infrastructure/` — адаптер хранения на Django ORM.
- `views.py`, `serializers.py`, `urls.py` — HTTP-адаптеры: аутентификация, валидация и формат ответа.
- `models.py`, `admin.py` — схема данных и интерфейс оператора.

В FastAPI те же роли разделены между `app/application/`, `app/infrastructure/` и `app/api/`. API-модуль является точкой сборки зависимостей. Новые сценарии добавляются в `application/`, доступ к внешнему каталогу — через порт и infrastructure-адаптер, HTTP-контракт — в API-модуле. Не помещайте бизнес-правила в view/route, не добавляйте межсервисный запрос из `backend_side/` и не отдавайте файлы пакетов через публичные static/media URLs.

## Локальные порты

| Приложение | Адрес | Назначение |
| --- | --- | --- |
| React сайт | `127.0.0.1:5173` | Публичные страницы; прокси только `/site-api/` |
| Django сайта | `127.0.0.1:4179` | Заявки и сайт-каталог |
| FastAPI платформы | `127.0.0.1:4178` | API платформы |
| Django база платформы | `127.0.0.1:4180` | Автомобили и firmware packages |

Все службы разработки привязаны к loopback. SQLite и локальное хранилище файлов используются только для MVP; production требует отдельной конфигурации PostgreSQL, объектного хранилища, TLS, резервного копирования, аудита и секретов.
